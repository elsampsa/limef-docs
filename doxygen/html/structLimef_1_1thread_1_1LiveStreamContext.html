◆ probe_duration_sec

int Limef::thread::LiveStreamContext::probe_duration_sec {15}

How long avformat_find_stream_info is allowed to probe for codec parameters, in seconds. On a lightly loaded system packets arrive quickly and the probe completes in well under a second. On a heavily loaded system (many parallel streams, valgrind, slow hardware) the server may be slow to deliver the first keyframe and the default FFmpeg probe window (~5 s) expires before width/height can be determined, causing a spurious retry loop. Increase this for production deployments with many concurrent streams or slow cameras.

The wall-clock interrupt deadline is set to 1.2× this value, giving FFmpeg time to hit its own internal limit before the hard abort fires.

Default: 15 s (3× the FFmpeg internal default).

◆ reconnect_interval_sec

int Limef::thread::LiveStreamContext::reconnect_interval_sec {0}

Mandatory reconnection interval in seconds. When non-zero, the stream is forcibly dropped and re-opened after this many seconds of continuous streaming. Useful for cameras (notably some Chinese IP cameras) whose streams start lagging or corrupting after long sessions. The reconnect follows the normal backoff path (onLost emitted, then onConnected once the new session is established). Default: 0 = never force-reconnect.

◆ use_ntp

bool Limef::thread::LiveStreamContext::use_ntp {false}

Use NTP wallclock from RTCP Sender Reports as the absolute timestamp.

When true, absolute timestamps are taken from the camera's NTP clock (delivered via RTCP Sender Reports). This enables wall-clock-aligned multi-stream synchronisation, but relies on the camera having a correctly configured NTP clock. A camera with a wrong clock (wrong year, large drift) will produce garbage absolute timestamps that break presentation scheduling — symptoms include a frozen first frame, pipeline stalls, or frames that never appear.

Before the first RTCP SR arrives (typically 1–5 s after stream open), the t0+PTS_delta fallback is used regardless of this setting, so early packets are always timestamped consistently.

Default: false (t0+PTS_delta, safe for all cameras). Set to true only when you know the camera's NTP is reliable.
