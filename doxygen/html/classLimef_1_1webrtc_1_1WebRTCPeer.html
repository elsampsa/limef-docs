Detailed Description

One WebRTC client connection — analogous to RTSPSession.

Owns a libdatachannel PeerConnection plus one shared_ptr<Track> per media track. The server-first offer flow:

  1. Construct with parsed track descriptions.
  2. Register setGatheringCallback(), then call beginOffer() — returns immediately; ICE gathering runs in the background (LAN: <100 ms, but not bounded — see WebRTCServerThread's own deadline handling).
  3. Once the gathering callback fires, call getLocalSdp() and send it to the browser; record the peer_id.
  4. When the browser POSTs its answer, call setAnswer().
  5. libdatachannel handles ICE + DTLS internally; state → Connected.
  6. Call sendRTP() on every incoming RTPFrame.

◆ beginOffer()

void Limef::webrtc::WebRTCPeer::beginOffer ( )

Generate the SDP offer and start ICE gathering.

Returns immediately — does NOT block. Register setGatheringCallback() before calling this. The callback fires (from a libdatachannel thread, same contract as setStateCallback()) once gathering completes; the caller is responsible for its own timeout, since libdatachannel gives no guarantee gathering ever reaches Complete (e.g. an unreachable STUN server).
