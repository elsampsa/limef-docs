Detailed Description

V4L2 Memory-to-Memory encoder.

Implements the Encoder interface using V4L2 M2M API. Developed against vicodec, deployable to Jetson with LIMEF_V4L2_NV.

V4L2 M2M uses two buffer queues:

  • OUTPUT: Raw frames go IN (confusing naming from V4L2)
  • CAPTURE: Encoded packets come OUT

State machine:

  1. Open device, set formats (CAPTURE first, then OUTPUT — Jetson driver requirement)
  2. Request and map buffers for both queues
  3. Start streaming on both queues
  4. Queue raw frame to OUTPUT, dequeue encoded from CAPTURE

LIMEF_V4L2_NV path (Jetson Orin NVENC):

  • OUTPUT: DMABUF via NvBufSurface PL + EGL+CUDA registration
  • CAPTURE: MMAP with EXPBUF fallback (NVMM-backed compressed buffers)
  • Input: AV_PIX_FMT_CUDA frames (GPU pointers, D2D copy only)

Example:

V4L2NVEncoderParams params;
params.device = "/dev/v4l2-nvenc";
params.codec_fourcc = V4L2_PIX_FMT_H264;
V4L2NVEncoder enc("v4l2-nvenc", params);
enc.setPacketFrame(packet_frame);
// First frame initializes dimensions
enc.push(&decoded_frame); // frame->format must be AV_PIX_FMT_CUDA
if (enc.status() == EncoderStatus::NeedsRead) {
const PacketFrame& pkt = enc.getPacket();
}

◆ requestKeyFrame()

void Limef::encode::V4L2NVEncoder::requestKeyFrame ( )
overridevirtual

Request that the encoder emit a keyframe on its next output.

LIMEF_V4L2_NV (Jetson NVENC): issues VIDIOC_S_CTRL of V4L2_CID_MPEG_VIDEOENC_FORCE_IDR_FRAME (V4L2_CID_MPEG_BASE+567, defined in NVIDIA's v4l2_nv_extensions.h) - the NVENC-specific control for forcing a true IDR, distinct from mainline V4L2_CID_MPEG_VIDEO_FORCE_KEY_FRAME used by V4L2Encoder/vicodec. Not verified on hardware — implemented from the NVIDIA Jetson Linux Multimedia API header/docs only (no Jetson device available in this dev environment).

Non-LIMEF_V4L2_NV build (vicodec fallback): uses the mainline V4L2_CID_MPEG_VIDEO_FORCE_KEY_FRAME control, same as V4L2Encoder.

Mutex-protected (ctrl_mutex_) since this may be called from a foreign thread concurrently with the driving thread's push()/status() calls, which also touch fd_.
