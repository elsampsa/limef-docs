Detailed Description

Minimal websocket text-broadcast server, with uWebSockets fully hidden.

Why this exists, next to WebSocketServerThread

WebSocketServerThread (websocket.h) is built for muxed fMP4/WebM video streaming: token auth, UUID<->slot mapping, per-stream init-segment caching, keyframe- synchronized client onboarding, multiple streams per instance. Its own public header pulls in uWebSockets' <App.h> directly - fine within limef's own build, but limef's install() step doesn't (currently) export uWebSockets' headers to downstream consumers (confirmed: ~/limef-stage/include/limef/uws/ stages as an empty directory), so anything that #includes websocket.h outside limef's own source tree won't actually compile.

WebSocketBroadcastServer is for the much simpler case: broadcast a text message to every currently connected client, nothing else - no per-client identity, no auth, one instance = one logical stream/port. Its entire uWebSockets dependency is hidden behind a pimpl (Impl, forward-declared here, fully defined in the .cpp where <App.h> is available) - this header includes nothing from uWS, so any downstream project (a plugin like LibMantis, an app, whatever) can use it with just "-lLimef" and no extra include path for uWebSockets/uSockets at all.

Threading model

startServer() spawns its own dedicated OS thread to run the uWS event loop (uWS::App::run() blocks forever) - intentionally separate from whatever thread constructs/owns this object. broadcastText() is safe to call from ANY thread: internally it marshals the actual uWS::WebSocket::send() calls onto the event-loop's own thread via uWS::Loop::defer(), the only thread-safe way to touch a uWS::WebSocket. Callers never see any of this.

Usage

auto logger = spdlog::default_logger();
Limef::thread::WebSocketBroadcastServer server(logger);
if (!server.startServer(8080)) { ... }
server.broadcastText(R"({"hello":"world"})"); // safe from any thread
// ...
server.stopServer();
