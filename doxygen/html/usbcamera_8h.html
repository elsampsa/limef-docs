Detailed Description

Thread for reading frames from USB cameras via V4L2.

Author
Sampsa Riikonen
Date
2025
Version
1.6.1

Overview

USBCameraThread reads raw frames from a USB camera device (e.g., /dev/video0) and sends them downstream as DecodedFrames carrying exactly what the camera delivers — no implicit format conversion. Any further conversion (e.g. YUYV→NV12) is done by an explicit downstream framefilter such as SwScaleFrameFilter.

Output Frames

  • StreamFrame: Sent once at startup with video dimensions, pixel format, fps
  • DecodedFrame: Continuous stream of raw pixel data in the camera's actual format

Pipeline Integration

Typical usage:

USBCameraThread → SwScaleFrameFilter(NV12) → DecodedUploadFrameFilter → ...
USBCameraThread → DecodedToTensorFrameFilter → ... // CpuSwScaleConverter handles any CPU format

Limitations

  • Supports raw pixel formats via single-plane V4L2_BUF_TYPE_VIDEO_CAPTURE mmap
  • MJPEG cameras not yet supported (would need internal decoding)
  • Audio capture not implemented (USB camera mics are separate ALSA devices)
