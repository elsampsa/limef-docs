Detailed Description

V4L2 Memory-to-Memory decoder.

Implements the Decoder interface using V4L2 M2M API. Hardware NVDEC decoder for Jetson Orin (tegra234) via V4L2 M2M API.

Codec identity and initial dimensions come from the AVStream passed at construction (matches FFmpegDecoder's signature). Initialization is lazy (on first packet) like V4L2Encoder.

V4L2 M2M uses two buffer queues:

  • OUTPUT: Encoded packets go IN (confusing naming from V4L2)
  • CAPTURE: Decoded frames come OUT

SOURCE_CHANGE and periodic SPS/PPS

The Jetson NVDEC driver fires V4L2_EVENT_SOURCE_CHANGE whenever it sees a new SPS in the bitstream — not only on actual resolution changes. Encoders that repeat SPS/PPS at every keyframe (GoPro, many IP cameras) therefore trigger a full CAPTURE teardown/rebuild at each GOP boundary. The mandatory V4L2 acknowledgment sequence is: STREAMOFF → REQBUFS(0) → REQBUFS(N) → EXPBUF/mmap/QBUF for each of the N capture slots → STREAMON. Approximate cost: ~(4N + 4) kernel ioctls + 2N mmap calls; for N=4 slots roughly 5–10 ms per event. If this overhead is unacceptable, strip redundant SPS/PPS NAL units from the packet stream before they reach the decoder (keep only the initial ones; I-frames decode without re-sending parameter sets).

Example:

V4L2NVDecoderParams params;
params.device = "/dev/video3"; // vicodec decoder
V4L2NVDecoder dec("v4l2-dec", stream, params);
dec.setDecodedFrame(decoded_frame);
// Push encoded packet (e.g., from V4L2Encoder)
dec.push(&packet_frame);
// Check for decoded output
if (dec.status() == DecoderStatus::NeedsRead) {
const DecodedFrame& frame = dec.getFrame();
}
