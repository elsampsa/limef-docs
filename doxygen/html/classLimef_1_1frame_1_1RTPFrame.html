Detailed Description

Frame containing RTP or RTCP packet data.

Used to carry individual RTP/RTCP packets from RTPMuxerFrameFilter to RTSPServerThread / WebRTCServerThread for transmission to clients.

This is very similar to RawFrame: just raw muxed bytes, but it carries some metadata set by the RTPMuxerFrameFilter.

One RTP packet is typically a small fragment of, say, sps+pps+iframe (if annex b) blob, or b-frame, or whatever. RTP receivers don't mind if the first byte blob they get is a part of a b-frame, i.e. midstream/frame.

However, it's better if the stream is self-contained, i.e. Annex-B = sps and pps come self-contained in the stream always together with the iframe.

Example usage:

RTPFrame rtp;
rtp.setData(packet_bytes, packet_size);
rtp.setTrackIndex(0); // video track
rtp.setPacketType(RTPFrame::PacketType::RTP);
pass(&rtp);

bool Limef::frame::RTPFrame::isSeqStart ( ) const
inlinenoexcept

True if this is the first RTP packet of a new access unit.

Set on the first writeCallback per av_write_frame() call. Use this to gate new-client delivery: wait until isSeqStart() before sending to a late-joining peer, avoiding mid-frame delivery. Not set for RTCP packets.
